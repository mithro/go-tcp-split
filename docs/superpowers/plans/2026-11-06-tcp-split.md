# tcp-split Implementation Plan

> **Revision 2026-11-06:** the fail-open control plane is removed by the owner ("Just make the rules permanent and the server run permanently"). The package ships two units, `tcp-split.socket` and `tcp-split.service` (now with `[Install] WantedBy=multi-user.target`), which the site enables at boot; there is no `tcp-split-redirect.service` and no `BindsTo=`/`Wants=` coupling to one. The nftables rules are the site's permanent firewall configuration, with `packaging/examples/redirect.nft` as the example. Spec Goal 4 ("Fail open") and the matching anti-goal are withdrawn. Text below (the Architecture line, Task 8 and Task 12) that describes the redirect unit or the fail-open chain is superseded and kept only as the record of the original plan.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, package and publish `tcp-split`, a sandboxed split-TCP relay for connections redirected by nftables on a VPN server, and prove its systemd sandbox on the VPN server.

**Architecture:** A stdlib-only Go daemon accepts on systemd-passed sockets, reads each connection's original destination with `SO_ORIGINAL_DST` / `IP6T_SO_ORIGINAL_DST`, applies safety checks, dials the destination and relays with half-close. Packaged with nfpm per the `mithro/apt-repo-action` Set B conventions, with three systemd units (socket, sandboxed service, fail-open redirect loader). A Python network-namespace harness proves IPv4 and IPv6 interception end to end.

**Tech Stack:** Go 1.27 (stdlib only), systemd socket activation, nftables, nfpm, GitHub Actions + `mithro/apt-repo-action`, Python 3 for the netns harness.

**Spec:** `docs/superpowers/specs/2026-11-06-tcp-split-design.md`

## Global Constraints

- Module `github.com/mithro/go-tcp-split`; `go.mod` has **no** `require` lines (stdlib only). Binary, package and command name `tcp-split`; nft table `inet tcp_split`.
- Build: `CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X github.com/mithro/go-tcp-split/internal/cli.Version=<v>" -o dist/tcp-split ./cmd/tcp-split`. `tcp-split --version` prints exactly `tcp-split <Version>` and exits 0.
- Flags are spelled `--long`. Defaults from the spec: `--connect-timeout 10s`, `--keepalive 60s`, `--idle-timeout 0`, `--max-conns 4096`, `--stats-interval 5m`, `--drain 30s`, `--congestion ""`, `--deny` repeatable, `--listen` repeatable, `--verbose`.
- Logging: `log/slog` `TextHandler` to stdout, `key=value`. Per-connection line at close with keys `client`, `dst`, `up`, `down`, `dur`, `result`; `result` is one of `ok`, `connect-failed`, `denied`, `not-redirected`, `limit`, `idle`, `error`.
- "Reset" = `SetLinger(0)` then `Close()` on the client `*net.TCPConn`.
- Packaging follows `mithro/apt-repo-action` `docs/packaging.md` Set B exactly as the sibling repository `go-tmux-saver` does: `.github/apt-packaging.toml` with `kind = "B"`, `deb.yml` named `Debian packages` with jobs `test`, `build-deb`, `publish-apt`, `release`, default suites and architectures, `version_schema: none`, `packaging/release-assets.sh`, GitHub Release `build-<version>`, every push to `main` publishes.
- Commits: small, one logical change each, Conventional-style subjects as the sibling repos (`feat:`, `test:`, `docs:`, `ci:`, `packaging:`), with the attribution trailer from the session.
- Work happens on a feature branch in its own worktree (create with `superpowers:using-git-worktrees`), never on `main` directly. Nothing is merged to `main` and nothing is run on the VPN server without the operator's go.
- Never redirect stderr to `/dev/null`; never use `/tmp`; scratch files go in the worktree's `tmp/`.

## Review Focus

1. **IPv4-mapped IPv6 destination** (`::ffff:1.2.3.4` read from an IPv6 socket): must be refused as invalid, never dialled as IPv4 through a different family's rules. Test in Task 4.
2. **Upstream reset mid-transfer**: the client must be closed promptly, the connection logged with `result=error`, and no goroutine leaked. Test in Task 5.
3. **Client data sent before the onward dial completes** (kernel-buffered): must be delivered once connected, in order. Test in Task 6.
4. **Blackholed destination** (dial never completes): the client must be reset after `--connect-timeout`, not hang. Test in Task 6.
5. **SIGTERM with live connections**: new accepts stop, live relays finish within `--drain`, then everything closes and the process exits 0. Test in Task 6 and Task 7.

### Task 6: Proxy server

**Files:**
- Create: `internal/proxy/proxy.go`, `internal/proxy/stats.go`, `internal/proxy/proxy_test.go`

**Interfaces:**
- Consumes: `relay.Run`, `relay.Reset`, `policy.Checker.Check` (as a func), `sockopt.OriginalDst`, `sockopt.SetCongestion`.
- Produces:
  ```go
  type Options struct {
      Lookup         func(*net.TCPConn) (netip.AddrPort, error) // default sockopt.OriginalDst
      Check          func(netip.AddrPort) error                  // default: allow all
      Dial           func(ctx context.Context, dst netip.AddrPort) (*net.TCPConn, error) // default: net.Dialer with ConnectTimeout
      ConnectTimeout time.Duration
      Keepalive      time.Duration
      IdleTimeout    time.Duration
      MaxConns       int
      Congestion     string
      Logger         *slog.Logger
      Verbose        bool
  }
  type Server struct{ ... }
  func New(o Options) *Server
  func (s *Server) Serve(ctx context.Context, ls []net.Listener) error // blocks; returns after Shutdown or ctx done
  func (s *Server) Handle(c *net.TCPConn)                              // one connection, synchronous
  func (s *Server) Shutdown(drain time.Duration)                      // stop accepting, wait ≤ drain, then force-close live relays
  type Stats struct{ Accepted, Active, Completed, Failed int64; FailedBy map[string]int64; Up, Down int64 }
  func (s *Server) Stats() Stats
  func (s *Server) LogStats()                                          // one line: msg=stats plus every Stats field
  ```
  `Handle` order: `Lookup` (error → `result=not-redirected`, reset), `Check` (`policy.ErrLoop`/`ErrInvalid`/`ErrDenied` → `result=denied`, reset), limit (→ `result=limit`, reset), `Dial` (error → `result=connect-failed`, reset), `TCP_NODELAY` + keepalive both sides, `SetCongestion` on the client side when `Congestion != ""`, `relay.Run`, then the close log line with `result` from the relay: `Err == nil` → `ok`, `relay.ErrIdle` → `idle`, anything else → `error` (plus key `err=`). Every reset path logs the same line with `up=0 down=0`.
